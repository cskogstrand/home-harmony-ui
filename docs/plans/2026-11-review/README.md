# 2026-11 review: implementation plan (master)

Working document for agents. Source: an Impeccable critique of the whole app (score 26/40) plus a read-only inventory of what the connected Home Assistant exposes. The owner chose to do **all** design fixes, **all four** Home Assistant additions, and to **move Automations, Integrations and History into Settings**.

Read this file first, then only the workstream file you are working on. Each workstream is self-contained: goal, decisions, file anchors, checklist, acceptance criteria.

## How to work this plan

1. Pick the first workstream in the table below whose status is not ✅ and whose dependencies are done. Mark it 🚧 in the table and commit that change alone (`docs: start <workstream>`), so parallel agents do not collide.
2. Read the workstream file and the repository docs it names (see [AGENTS.md](../../../AGENTS.md) for the doc map). Read [DESIGN.md](../../../DESIGN.md) and the matching `.impeccable/surfaces/*.md` brief before any UI edit.
3. Work one checkbox at a time. When a box is done **and verified**, tick it (`- [x]`) in the same commit as the code. Small boxes may share a commit; never tick a box whose verification failed.
4. Commit on `main` (repository rule). Conventional subjects, as in `git log`: `feat: …`, `fix: …`, `refactor: …`, `docs: …`, `test: …`. Body says what changed and why.
5. When every box in a workstream is ticked, set its status to ✅ in the table below and commit.
6. If you must stop mid-workstream, leave a short `> Handoff:` note directly under the last ticked box describing state and next step, and commit it.
7. If a box turns out wrong or unnecessary, do not silently delete it: strike it (`- [x] ~~text~~ — skipped: reason`).

### Verification per box (pick what applies)

```sh
npx vitest run src/test/<relevant>.test.tsx
npx tsc --noEmit -p tsconfig.app.json
npm run lint
```

Before marking a workstream ✅, also run `npm run --silent test:silent` and, when server files changed, `npm run --silent test:server:silent`. UI changes: check in the browser at 1440 × 2560 (portrait wall) and 390 × 844 (phone), light and dark, and once with artwork on (Settings → Appearance).

### Hard rules (from AGENTS.md and PRODUCT.md)

- **No real household data** in code, tests, docs, screenshots or commit messages. Fixtures must be fictional (see `src/test/ha-fixtures.ts`, `src/test/device-card-fixtures.ts`).
- The local dev server is connected to a **real** Home Assistant. Browser checks there are read-only: never toggle devices, run scripts/automations, arm/disarm, or save settings against it. Prove behaviour with unit tests and fictional fixtures.
- Physical commands are never replayed automatically. Failed writes keep drafts. Destructive actions keep confirmation.
- Every new user-facing string goes through i18n with an entry in both `src/locales/en.ts` and `src/locales/nb.ts`.
- Update the docs that describe changed behaviour (README.md, PRODUCT.md, DESIGN.md, DOCS.md, docs/*.md). CHANGELOG.md is generated by the release workflow; do not edit it by hand.
- Run only one dev server against the data directory (see [00-preflight](00-preflight.md)).

## Background: findings that drove this plan

Design critique (Nielsen 26/40, Acceptable):

- **P1** Week grid at 1440 px portrait has 158 px day columns; titles break mid-word, waste pickups take full cards, an add button fills every empty cell. → 01
- **P1** With artwork on, `.list-tabs` gets the card colour so the selected tab's fill vanishes; selection is nearly colour-only. Card-coloured patches sit behind section links. → 02
- **P1** Bell shows a filled "…" badge while a rule only waits for a reading, identical to a real alert. Header and vehicle strip push the next plan below the fold on phone. Same-day waste pickups repeat. → 03
- **P2** Scenes render three different ways; `/alarm` uses four equal pills, keeps the current-state action enabled, and shows state as small body text. → 06
- **P2** Raw English HA states, untranslated entity names and inconsistent number formatting; admin pages (run/disable automations) one tap from the family dock. → 04, 05
- **P3** Detector: ~40 distinct font sizes outside the documented ramp, off-scale radii, a 10.4 px caption on the robot map. → 12

Home Assistant capabilities available but unused by the app (verified read-only against a live instance; this list is generic on purpose):

- Conversation agents, speech-to-text and text-to-speech engines → 07
- Logbook event stream (today `/history` is only an outbound link) → 08
- Per-circuit power sensors; no price sensor and no Energy dashboard preferences configured yet → 09
- Repairs issues, persistent notifications and backup status (`backup/info`) → 10
- A 3D printer integration exposing progress, stage, temperatures, filament trays, camera and cover image; today only used by an ongoing notification → 11
